# BP12 bit-identical 回歸證明

> 交付物 ②。兩條紅線各一份證明：(A) trigger_reasons 修復不得移動動能等級；
> (B) R_TRACK 開關不得移動動能等級。皆以凍結資料（`--reuse-data` 凍結價格快取 +
> 暖機籌碼 DB）重跑，各對比只差「一個變數」。

## 證明 A：trigger_reasons 修復對動能管線零影響

同一當前環境（同 pickle、同 DB、同 config），僅差 `analyzers.py` 的 4 行修復。

| 等級 | 修復前 `bp12_t1_beforefix` | 乾淨修復後 `bp12_t1_afterfix2` | 交叉核對 `bp11_baseline`(7/10) | 結果 |
|---|---|---|---|---|
| A | 1305 | 1305 | 1305 | ✅ |
| B | 12459 | 12459 | 12459 | ✅ |
| C | 30840 | 30840 | 30840 | ✅ |
| SELL | 25971 | 25971 | 25971 | ✅ |
| WAIT | 8112 | 8112 | 8112 | ✅ |
| SKIP | 52306 | 52306 | 52306 | ✅ |
| 合計 | 130993 | 130993 | 130993 | ✅ |

**BIT-IDENTICAL。** 修復前精準重現 7/10 的 bp11_baseline，證明環境確定性穩定。

### 異常 run 揭露（誠實記錄）

首次「修復後」run（`bp12_t1_afterfix`）曾出現 A=458、WAIT=25681 等大幅位移，一度像是修復破壞動能。診斷推翻：

1. 位移的 32,380 筆中**僅 2.5% 為超跌股**（bias<−10），低於未位移族群（4.5%）；但 trigger_reasons 修復**數學上只可能影響超跌/left_buy 訊號**，不可能移動那 97.5% 的非超跌訊號。
2. log 零錯誤；A 級（動能突破，與超跌無關）不可能被此修復觸及。
3. 乾淨無干擾重跑（`afterfix2`）與修復前完全一致。

→ 該次為一次性未受控環境異常（非修復所致）。此調查即是在守這條紅線。

## 證明 B：R_TRACK 開/關對動能等級零影響

同一 commit（含 R 軌接線），僅差 `R_TRACK` 環境變數。

| 等級 | R_TRACK 關 `afterfix2` | R_TRACK 開 `bp12_r_on` | 結果 |
|---|---|---|---|
| A | 1305 | 1305 | ✅ |
| B | 12459 | 12459 | ✅ |
| C | 30840 | 30840 | ✅ |
| SELL | 25971 | 25971 | ✅ |
| WAIT | 8112 | 8112 | ✅ |
| SKIP | 52306 | 52306 | ✅ |

**BIT-IDENTICAL。** R 軌評估只寫獨立欄位（`r_signal`/`r_strength`），不觸碰 grade/action_code，
故開關 R 軌對動能裁決零影響——與「R 軌獨立於動能」紅線一致。

## 方法

- `--reuse-data`：凍結價格快取 `_histcache_*.pkl`（各輪同一份），籌碼讀暖機 `watchlist_v4.db`。
- 各對比只變動一個變數（修復 or R_TRACK），其餘完全相同。
- 六級筆數合計 130,993 於所有 run 一致，佐證資料未漂移。
