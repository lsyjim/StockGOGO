## 3. 為什麼零差異：P1/P2/P3 情境在真實資料中不存在

對凍結資料集抽樣 n=3,951，直接量測各候選條件的共現頻率（不依賴補丁，純讀 `result`）：

| 條件 | 出現次數 | 佔比 |
|---|---|---|
| 三盤突破（量能待確認） | 332 | 8.40% |
| 帶量突破 VP05 | 173 | 4.38% |
| D20 突破（帶量） | 101 | 2.56% |
| D55 突破 | 75 | 1.90% |
| **Group P1**（待確認 + VP05） | **0** | **0.00%** |
| **Group P2**（待確認 + D20） | **0** | **0.00%** |
| **Group P3**（待確認 + VP05 + D20） | **0** | **0.00%** |

**結構性原因（不是巧合）**：「三盤突破**量能待確認**」的定義是
`detected and not volume_confirmed`（突破了但**沒有量**）；
而 VP05 是「**帶量**突破」、D20 也是「**帶量**突破」。
**「沒有量」與「帶量」在同一根 K 棒上互斥**，因此待確認永遠不可能
壓掉 VP05 或 D20——這個優先序 bug 是**邏輯上不可達（unreachable）**的。

⚠️ 抽樣為 n=3,951；但全樣本 130,993 筆的輸出逐位相同，已是全集合層級的零影響證明，抽樣僅用於解釋**為什麼**為零。

## 4. 依預先定義準則的結論

spec 預先定義了兩種情況，但兩者都預設「受影響子集非空」。
實測結果落在第三種情況：**受影響子集為空集合**。因此：

| 判斷面向 | 結果 |
|---|---|
| 受影響子集後續報酬 | 無樣本可比較（n=0） |
| 新增 A 級樣本品質 | 無新增 A 級（grade 差異 0 筆） |
| OOS/regime 方向一致性 | 不適用 |
| 整體 portfolio | 完全相同（逐位元組） |

**結論：建議修正規格文件（註解），不修改程式碼。**

理由：
1. 修改程式碼的預期效益**經全樣本量測為精確的零**，
   而任何改動都帶有回歸風險（本專案已有多次「改動引發連鎖問題」的紀錄）。
2. 兩者互斥是**語意上的必然**（有量 vs 沒量），不是資料期間的偶然；
   未來資料也不會讓它變成可達路徑，除非「量能確認」的定義本身改變。
3. 現行實作的行為是正確的；錯的是註解宣告的優先序。

**具體修正**：`decision_engine.py` 中兩處優先序註解（`score_timing` 內
「取較強者敘述：D55 > 三盤帶量/VP05 > D20 > 三盤待確認」）應改為與實作一致的
實際判定順序，並補一行說明「三盤待確認與 VP05/D20 因量能條件互斥，
故其相對順序不可達」。

> **最終必須是 Specification = Implementation。** 本輪數據支持的是
> **讓文件對齊實作**，而非讓實作對齊文件。

## 限制

- 本結論成立的前提是「量能待確認」與「帶量突破」的定義維持互斥。
  若日後修改 `volume_confirmed` 或 VP05/Donchian 的量能門檻，
  此優先序即可能變成可達路徑，屆時需重新評估。
